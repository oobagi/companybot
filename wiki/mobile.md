# Mobile

The pilot is an Expo SDK 58 / React Native 0.88 application with Expo Router. The signed-in client includes chats, collaborative pages, databases and workspace settings. See [Mobile parity](mobile-parity.md) for implementation and acceptance status.

## Structure and boundaries

- `apps/mobile/src/app`: route files and root navigation only. Put features in `src/features` and native UI in `src/components` and shared controls in `src/components/ui`. `src/design` owns semantic tokens; native navigation helpers live in `src/components/navigation`.
- `apps/desktop`: existing Electron client, with its own UI and release lifecycle.
- `packages/core`: existing domain and agent logic. Mobile should use explicit browser-safe subpath exports, never the agent runtime barrel or server I/O modules.
- `packages/backend`: existing Convex deployment and generated client contracts. Clients may import generated API references and types; never import backend handlers.

Keep UI platform-specific. Extract shared client logic only when both clients use it. Server state belongs in Convex; transient screen state stays local. Mobile authentication must use secure native token storage and preserve the existing per-request workspace authorization before adding workspace features. No secrets belong in EXPO_PUBLIC variables.

## Development

Install from the repository root with `pnpm install --frozen-lockfile`. Run `pnpm dev --mobile` for the local Convex backend and Metro together, or `pnpm dev:mobile` for Metro against an already running backend. Set `EXPO_PUBLIC_CONVEX_URL` in `apps/mobile/.env.local` for a remote development backend; never put secrets in public environment variables. From `apps/mobile`, use `pnpm ios` or `pnpm android` to generate and build native projects (Xcode or Android SDK required). SDK 58 is in the Expo Go transition period, so use a native development build if the installed Expo Go supports only SDK 57.

When updating an existing local database across schema changes, run `pnpm exec convex run migrations:runAll` against that local deployment and check `migrations:status`. The retained migrations initialize custom roles and upgrade skills, wakeups and page data; clients must not seed partial replacements.

Native `ios/` and `android/` folders are generated and ignored. Change app.json and config plugins instead of editing generated code. Bundle identifiers are provisional `com.companybot.mobile`; confirm ownership before store registration. Signing, store submission, push credentials, EAS project registration and OTA publishing still require project configuration. Notification registration, authenticated routing, delivery retries and receipts are implemented, but remote push delivery is not verified until APNs/FCM credentials and `extra.eas.projectId` are configured.

## Validation and upgrades

`pnpm typecheck` covers all workspaces. `pnpm test` covers domain, backend, desktop and mobile tests. `pnpm --filter @companybot/mobile export` bundles iOS, Android and web in CI; it does not prove a native build or device behavior. Native simulator and physical-device checks remain required before shipping.

Use `pnpm exec expo install <package>` from apps/mobile for native dependencies, followed by `pnpm exec expo install --check` and `pnpm dlx expo-doctor`. Keep React and React Native on the SDK-supported versions, even when desktop uses a newer React patch. Use one root lockfile and pnpm isolated workspaces; no Metro resolver overrides or extra task orchestrator are needed here. The backend explicitly pins the React/React DOM development peers required by its collaboration component to the mobile SDK pair, so its generated-contract dependency does not introduce a second React into mobile autolinking. Desktop keeps its own supported renderer version. Review major dependency upgrades with typecheck, tests and desktop/mobile bundles.

## Native interaction policy

Prefer real platform controls over recreating their appearance. SDK 58 uses `expo-router/native-tabs` (the stable import), a native stack per tab, system search bars, and `Stack.Toolbar` buttons/menus. iOS receives SF Symbols and native glass treatments where supported; Android receives Material Symbols and system navigation behavior. Keep platform defaults for gestures and transitions.

`@expo/ui` supplies SwiftUI and Jetpack Compose controls behind shared component APIs: choice menus, sheets, dates and buttons. Settings uses a small shared React Native list library with native symbols and switches, following the local Stuff and HKT composition patterns. Simple confirmation decisions use native alerts; asynchronous destructive operations retain a sheet with busy locks and visible errors. Required choices cannot be cleared accidentally. Long lists and multiple selections use searchable sheets. React Native TextInput and Switch already render native controls; retain them where their editing and accessibility behavior fits.

The document editor is an intentional Expo DOM boundary: existing BlockNote/ProseMirror documents must keep their exact schema and collaboration protocol. Native callbacks expose only the selected page and validated operations; credentials stay outside the WebView. Navigation guards protect pending edits; native WebView teardown flushing remains best effort.

The editor and version previews use Expo's default DOM WebView on both native platforms. A tracked pnpm patch to Expo 58.0.23 handles its native `injectJavaScript` promise: the upstream wrapper assumes a void return, leaving late results unhandled after navigation removes the view. Prop updates wait for `DOM_READY`, when the DOM listener and native view exist; initial props still come from the embedded payload, and the readiness event replays the latest values. Callback results remain independent of prop readiness. A layout-effect cleanup marks the bridge detached during React’s removal commit, before passive callbacks can target the removed native view. The patch stops injections after unmount/ref detachment and suppresses only a missing-DomWebView rejection from an already detached view; live-view failures and unrelated exceptions remain visible. Keep the editor's save/navigation guards: bridge teardown handling does not guarantee a final save after removal. Reassess the patch when upgrading Expo.

All serializable editor props cross that boundary as one URI-encoded JSON payload (`domPayload.ts`); capability callbacks stay top-level. Encoding before injection preserves exact document/reference text across WebView serializers and prevents user text from becoming JavaScript interpolation; decoding happens only inside the DOM component. Regression tests exercise nested JSON, quotes, backticks, interpolation, slashes, newlines and Unicode, plus late native rejection handling. Credentials remain outside this payload.

Native document views use BlockNote’s single `bn-scroll-container`, which follows the visual viewport. A shared floating native toolbar owns formatting, insertion and block menus; the web build retains BlockNote's formatting toolbar. Native link editing maps the captured selection through collaborative transactions while its sheet is open. The DOM component updates Expo’s existing viewport meta tag with `interactive-widget=resizes-content` rather than adding a conflicting second tag; this change stays inside the native DOM boundary. See [BlockNote mobile compatibility](https://www.blocknotejs.org/docs/getting-started#mobile-compatibility). Complete software-keyboard and long-document acceptance remains outstanding.

Native editor process termination overrides Expo's automatic reload. The surface immediately unmounts the failed WebView, disables editing controls and offers an explicit reload of the saved document, with confirmation when pending work is protected. Native action sheets retain their drafts but disable submission when the editor is unavailable; cancelling still uses the discard guard. A sub-page already committed during interruption is reported as created and cannot be submitted twice. Obsolete commands and callbacks cannot replay into the replacement editor. Regression tests exercise both platform termination callbacks. Forced Android renderer crashes and iOS WebContent termination verified removal of the failed editable view, survival of the app process and explicit saved-document recovery. Both platforms retained an open link draft with submission disabled and guarded discard. An Android pending native submit also survived renderer termination: after the local backend resumed, the text returned once and was readable on iOS. Each changed unsynced document now sends a rich recovery copy across the native bridge, including later edits buffered behind an unresolved submit. On renderer loss, the native owner freezes that copy for read-only review and rich clipboard export; reload warns before discarding it, while navigation retains completed device copies. This does not replay edits into the shared document. Android native QA verified review, copy, paste into a new page and Back/reopen persistence. Native recovery copies now persist in app-private JSON files scoped by deployment, account, workspace, page and editor instance. Writes are serialized and finalized to unique revision files before older valid copies are pruned. Successful synchronization clears only the current editor’s copy. On reopening with current page access, users explicitly review/copy or discard abandoned drafts before opening the shared document; there is no automatic replay. Navigation and sign-out retain completed account-scoped copies. “Saved on device. Waiting to sync…” appears only after the latest copy finishes writing. Android verified full app restart with a held backend submit, including later buffered edits, review/copy, navigation retention and explicit discard. Web remains memory-only. Files are not application-encrypted and contain no auth credentials. Unreadable finalized copies are retained; a visible error offers Retry or deliberate Open saved document without deleting those files; unfinished temporary revisions are ignored and retained. Edits not yet delivered across the bridge or finalized to disk can still be lost. This does not provide offline app startup or offline collaboration. iOS recovery-copy UI acceptance, OS memory-pressure and physical-device acceptance remain outstanding.

Image validation uses bounded `FileHandle.readBytes` on native and Blob slicing on web. Expo File's `slice()` constructs a Blob from an ArrayBuffer, which React Native rejects. Document and Settings uploads share `lib/imageFile.ts` and the core image limits.

Date and time inputs share a platform adapter: iOS uses Expo SwiftUI DatePicker with a field title and localized accessibility value, while Android retains the native dialog. Compact iOS pickers keep hidden visual labels because the React Native row owns their visible label. Full screen-reader acceptance remains required.

A tracked `expo-symbols@58.0.4` patch disables text scaling only for its decorative Material Symbol glyph. Upstream renders the glyph as scalable Text inside a fixed-size View, clipping icons at accessibility text sizes; 58.0.5 has the same implementation. Body text still scales normally. Reassess the patch when upgrading Expo Symbols.

For Android software-keyboard QA, open the bound device session with `--no-test-ime`. The automation tool otherwise uses a headless input method by default. If it was already enabled, close this thread's session first, then reopen with that flag; changing the flag on an already active session alone did not restore the real keyboard.

The `with-android-font-scale` config plugin handles Android font changes without recreating the activity and losing routes or unsaved form state. It remeasures the React surface, refreshes DeviceInfo's cached font scale for responsive layouts, and updates embedded WebViews' text zoom without reloading documents. RN 0.88's native change detector compares 1sp, which can remain unchanged with Android nonlinear scaling; DeviceInfo otherwise refreshes only on resume. Recheck these workarounds on RN/Expo upgrades. This is not draft persistence across process death. SDK 58 prebuild recreates native directories by default; use `--no-clean` for incremental local rebuilds.

Android ChoiceMenu also keys its read-only trigger by font scale: unchanged text hosted in Expo UI's RNHostView otherwise retained its old size. The native menu and parent form remain mounted. Emulator checks verified resizing in both directions, an open menu retaining its selection, and an open form retaining text/choice drafts. Reassess this narrow workaround on Expo UI upgrades; do not key the menu or editable form itself.

The `with-android-link-intent` plugin retains new Android intents before forwarding them to React Native. A deep link received during JavaScript startup can otherwise miss the URL event listener, while `Linking.getInitialURL()` still reads the original launcher intent with no URL. Retaining the latest intent lets Expo Router initialize from that link. The plugin does not change authentication or workspace authorization. For Android cold-link QA, pass the URL positionally: `agent-device open com.companybot.mobile companybot://pages --relaunch`; the tested `--launch-url` invocation did not deliver an initial URL on Android.

Native sign-in retains the latest supported `companybot://` destination in memory outside the protected navigator, then consumes it once after authentication and workspace hydration. It clears on sign-out, leaves signed-in URL events to Expo Router, and never forwards arbitrary navigation-control parameters. The canonical `companybot://page/<id>` format used in saved documents has a route alias to the existing guarded page screen. This does not automatically select another workspace; document queries still use the selected workspace and its access checks. See [Expo protected routes](https://docs.expo.dev/router/advanced/protected/) and [SDK 58 Linking](https://docs.expo.dev/versions/v58.0.0/sdk/linking/).
